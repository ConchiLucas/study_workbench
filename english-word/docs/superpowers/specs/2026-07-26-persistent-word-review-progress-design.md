# 待复习错词持久状态与逐词复习设计

## 目标

错题集表达“仍未完成复习的错词集合”，不是错误事件历史。

一个单词只要符合错词队列入口条件，就进入当前用户的待复习错题集。它必须依次完成：

1. 立即复习；
2. 7 天复习；
3. 15 天复习。

三个阶段全部答对后，该词才从错题集移除。已完成单词再次答错时重新激活。

三词句子的复习进度按单词独立维护：一个词答错只重置这个词，另外两个词继续各自阶段。

## 当前问题

现有实现有三类状态，但没有统一表达单词是否完成复习：

- `wrong_word_events.status` 只表示造句队列的处理状态；
- `sentence_cloze_review_schedule` 按整句记录复习状态；
- `/api/wrong-words/events` 返回每次错误事件流水。

当前还有两个生命周期缺口：

- 生成后的挖空题首次直接答对时没有复习计划，会被立即视为掌握；
- 第一次复习答对并安排 7 天后，现有到期查询要求“最近一次仍为错误”，导致 7 天、15 天任务无法重新出现。

因此不能通过修改列表 SQL 解决，需要建立单词级复习事实表。

## 方案选择

### 方案一：动态拼接全部历史

从普通答题、挖空答题、造句内容和整句计划动态推导当前状态。

优点是不新增表；缺点是无法可靠区分“从未开始”和“已经完成”，并且 JSON 关联和跨事件聚合复杂，不采用。

### 方案二：在整句计划中保存单词 JSON 状态

继续使用 `sentence_cloze_review_schedule`，新增 JSON 字段记录三个词的阶段。

表数量少，但条件查询、局部更新、并发控制和数据校验都较困难，不采用。

### 方案三：新增单词级复习进度

为每个用户和标准化单词维护独立进度；句子只是承载练习的内容。

该方案语义清晰，可直接查询待复习集合，支持逐词推进和重复答错重置，采用此方案。

## 数据模型

新增 `wrong_word_review_progress` 表，核心字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 进度 ID |
| `user_id` | 用户 ID |
| `word_id` | 词库单词 ID，可空 |
| `word` | 展示单词 |
| `normalized_word` | 小写并去除首尾空白后的唯一键 |
| `status` | `waiting_sentence`、`due`、`waiting`、`completed` |
| `review_stage` | `0` 立即、`1` 等待 7 天、`2` 等待 15 天、`3` 已完成 |
| `next_review_time` | 下一次允许推进的时间 |
| `active_cloze_item_id` | 当前承载该词复习的句子 ID，可空 |
| `active_blank_index` | 该词在当前句子标准答案数组中的下标 |
| `wrong_count` | 累计进入错词链路次数 |
| `first_wrong_time` | 首次答错时间 |
| `last_wrong_time` | 最近答错时间 |
| `last_answer_record_id` | 最近一次推进或重置该词的挖空答题记录 |
| `completed_time` | 完成三轮的时间 |
| `create_time` / `update_time` | 审计时间 |

唯一约束为 `(user_id, normalized_word)`，保证错题集按单词聚合成一行。

`sentence_cloze_review_schedule` 保留，继续服务不属于错词队列的独立句子训练；`word-agent` 来源的句子改用单词级进度判断。

## 状态生命周期

### 进入错词链路

普通答题或挖空答题产生可入队错词时，在提交答题事务内 upsert 单词进度：

- 新单词：`waiting_sentence`、阶段 0；
- 未完成单词再次答错：累计错误次数，阶段重置为 0；
- 已完成单词再次答错：清除完成时间并重新激活；
- 如果已有可用句子，重置后状态为 `due`；否则为 `waiting_sentence`。

进度写入不依赖异步 Word Agent 通知是否即时成功，避免通知暂时失败导致错词从用户错题集中丢失。造句队列仍按现有机制重试。

### 句子生成

`SentenceClozeService` 保存 `word-agent` 句子后，按 `blank_words_json` 下标关联每个单词进度：

- 设置 `active_cloze_item_id` 和 `active_blank_index`；
- 阶段保持或重置后的阶段 0；
- `next_review_time` 设置为当前时间；
- 状态改为 `due`。

旧批次晚到时不得覆盖更新事件对应的更新进度；实现中使用更新时间或队列事件顺序做幂等保护。

### 提交答案

后端按标准答案数组逐空比较，不再只使用整句 `is_correct` 推进三词状态：

- 到期词答对：
  - 阶段 0 → 阶段 1，下一次为 7 天后；
  - 阶段 1 → 阶段 2，下一次为 15 天后；
  - 阶段 2 → 阶段 3，状态改为 `completed`；
- 任意未完成词答错：
  - 阶段重置为 0；
  - 下一次复习时间为当前时间；
  - 状态改为 `due`；
  - 继续发送新的错词队列事件；
- 尚未到期的词答对不提前推进；
- 尚未到期的词答错仍然重置，因为新的错误证明该词尚未掌握。

整句总结果继续按现有规则保存，保证答题历史和统计兼容。

### 三词进度分离

一句三词中若两个词答对、一个词答错：

- 到期且答对的两个词分别进入自己的下一阶段；
- 答错词单独重置为立即复习；
- 下次只要句子内任意关联词到期，该句子就可以进入任务列表；
- 页面仍展示完整句子，后端只推进已到期的正确词，但会重置任何答错词。

## 错题集接口

用户端错题集改为查询 `wrong_word_review_progress.status <> 'completed'`，而不是返回事件流水。

同一用户同一标准化单词只返回一行。保留此前确认的七个展示字段：

1. 来源单词；
2. 最近答错时间；
3. 入口/模式；
4. 词库/难度；
5. 词难度；
6. 耗时；
7. 正确答案。

展示字段取该词最近一次可入队错误记录；总数按未完成的唯一单词数计算。搜索、最近错误排序、错误次数排序和分页继续保留。

管理后台用户错题集使用同一未完成口径；此前删除的“你的答案”列不恢复。

可在接口内部额外返回 `reviewStatus`、`reviewStage` 和 `nextReviewTime`，供后续页面展示，不要求本次新增可见列。

## 复习任务查询

`word-agent` 句子的待练和到期判断改为：

- 至少关联一个未完成单词；
- 至少一个关联单词 `next_review_time <= NOW()`；
- 不再要求句子最近一次答案为错误。

没有生成句子的 `waiting_sentence` 单词仍显示在错题集，但不会进入挖空任务；句子生成成功后自动转为立即可复习。

## 历史数据迁移

历史数据没有可靠的单词级“三轮已完成”标记，因此不能把“最近答对且无整句计划”直接当作完成——它也可能只是首次答对。

迁移采用保守策略：

- 从所有符合队列入口条件的普通和挖空错误记录按用户、单词聚合；
- 为每个唯一单词创建未完成进度；
- 能关联现有 `word-agent` 句子的，设置当前句子并立即到期；
- 无句子的设置为 `waiting_sentence`；
- 不猜测历史完成状态，历史错词重新按新规则完成三轮后才移除。

迁移脚本必须幂等，重复执行不增加错误次数、不覆盖更新的在线进度。

## 兼容与错误处理

- Python `wrong_word_events` 保持原有队列状态和重试规则；
- `failed`、`retry_wait`、`pending`、`processing`、`processed` 都不直接决定错词是否完成；
- 造句失败的单词持续显示为待复习；
- 旧整句复习计划不立即删除，避免影响独立训练和历史查询；
- API 保留响应分页外壳，前端只需要把数据源从事件行改成未完成单词行。

## 测试

### 后端

- 四类入口产生的可入队错词都会创建或重置单词进度；
- 同一用户同一单词多次答错仍只有一条进度，错误次数累加；
- 句子生成后三个词分别关联下标并立即到期；
- 首次答对只进入 7 天阶段，不会完成；
- 7 天答对进入 15 天阶段；
- 15 天答对后单词完成并从错题集消失；
- 三词部分错误时只重置错误词；
- 未到期词答对不推进、答错会重置；
- 已完成词再次答错会重新出现；
- 7 天和 15 天到期任务不受“最近一次答案必须错误”限制；
- 历史迁移幂等。

### 用户端与管理后台

- 错题集总数按未完成唯一单词统计；
- 同一单词多条错误历史只显示一行；
- 完成三轮后从列表移除；
- 搜索、排序、分页和七字段展示正常；
- 所有已确认位置仍不展示“你的答案”。

### 回归

- 独立句子训练继续使用现有整句计划；
- 答题历史、总正确率和已掌握单词统计不被破坏；
- Word Agent 队列生成、失败重试和非 Docker 本地启动保持可用。
