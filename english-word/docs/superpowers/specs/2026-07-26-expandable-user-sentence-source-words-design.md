# 用户造句结果按句子展开来源单词设计

## 背景

当前 6016 管理后台“用户造句结果”以普通宽表展示，每条
`sentence_cloze_item` 同时占用“单词、生成句子、挖空句、翻译、来源、模型”
多列。句子、挖空句和翻译都被截断，单词只是逗号拼接，无法直观看出每个生成
单词来自哪一次答错。

“用户错题集”已经采用“聚合主行 + 展开明细”的浏览方式。本设计让“用户造句
结果”使用相同信息层级：一句生成结果是一条主记录，展开后查看题目详情和组成
这句话的来源单词。

## 已确认需求

- 使用“句子主行 + 来源单词明细”的平衡型布局。
- 主行英文句子下直接显示中文翻译。
- 展开后先显示挖空句和中文解释，再显示来源单词表。
- 来源单词表以追溯原答错记录为核心，不做词典学习面板或编辑功能。
- 页面全部造句记录都采用新布局。
- 外部错题生成记录显示完整来源；没有错题事件链的历史记录显示
  “历史生成，无答题来源”。
- 使用服务端聚合嵌套数据；前端不按行或按词发起二次请求。
- 不为本功能增加数据库字段。

## 非目标

- 不修改句子生成、错词组批、重试、TTS 或挖空题落库流程。
- 不重新生成、删除或编辑现有句子。
- 不在本次增加“重新生成”“删除单词”或“修改句子”操作。
- 不实现来源记录的跨页面深链接。
- 不把历史无来源记录伪造成答错事件。
- 不修改 `sentence_cloze_item` 或 `wrong_word_events` 表结构。

## 页面信息架构

### 句子主行

每条 `sentence_cloze_item` 渲染一个可展开主行，列顺序如下：

| 列 | 内容 | 展示规则 |
| --- | --- | --- |
| 序号 | 当前分页序号或 `#ID` | 左侧同时承担展开层级提示 |
| 生成时间 | `createTime` | `MM/DD HH:mm:ss` |
| 用户 | `userName`，空值回退 `用户 {userId}` | 单行省略 |
| 句子 / 翻译 | 英文 `sentence` + 中文 `translationZh` | 英文最多两行、翻译最多一行；悬停展示全文 |
| 来源词 | 来源单词数量 | 显示为“1 个词”“3 个词”，不再在主行拼接单词 |
| 来源 | 当前来源中文名 | 例如“外部错题触发”“最佳例句练习” |
| 模型 | `model` | 单行省略，悬停显示完整值 |
| 操作 | 展开 / 收起 | 整条主行也可点击 |

主行删除当前独立的“单词、挖空句、翻译”三列。翻译并入句子列；挖空句进入
展开区；来源词只显示数量，避免与展开单词重复。

默认全部收起。点击主行或右侧操作切换当前句子；支持同时展开多条。翻页、改变
页大小、搜索或切换用户时清空展开状态，避免保留不可见记录的展开 ID。

主行使用真正的 `button` 语义或等价的键盘交互，设置 `aria-expanded` 和
`aria-controls`。展开区内部的文本选择、Tooltip 和未来操作不能冒泡触发收起。

### 句子展开区

展开区分为上下两部分：

1. 题目详情：
   - 挖空句：完整 `clozeSentence`。
   - 中文解释：完整 `explanationZh`；空值显示 `—`。
2. 来源单词与原答错记录：
   - 每个来源单词一行。
   - 顺序与生成请求中的 `words/sourceEventIds` 顺序一致。

来源单词列设计如下：

| 列 | 字段/来源 | 空值规则 |
| --- | --- | --- |
| 来源单词 | `sourceWords[].word` | 必填；回退父记录 `words` |
| 答错时间 | 错词事件 `created_at` | 历史记录显示 `—` |
| 入口 / 模式 | 事件来源 + 游戏 `mode` | 游戏显示匹配/单人训练；挖空显示“挖空练习”；无法区分 review/solo 时不猜测 |
| 词库 / 难度 | 游戏记录的训练难度组与等级 | 不存在显示 `—` |
| 词难度 | 错词事件 `word_difficulty` | 不存在显示 `—` |
| 耗时 | 游戏答题 `answer_time_ms` 或挖空答题 `cost_ms` | 不存在显示 `—` |
| 你的答案 | 错词事件 `selected_meaning` | 空答案显示 `—` |
| 正确答案 | 游戏事件 `correct_meaning`；挖空事件使用目标词 | 不存在显示 `—` |
| 来源追溯 | 事件 ID + 原答题/题目 ID | 历史记录显示“无答题来源” |

当前挖空错词通知没有保存 `review/solo` 页面入口，因此只能准确显示“挖空练习”，
不能推断“错题复习”或“单独训练”。本功能不修改通知契约来补录这个字段。

展开表允许自身横向滚动，主页面不因为九列单词明细整体溢出。桌面宽屏显示完整
列；较窄窗口保持主句可读，用户只在展开区内横向查看来源字段。

### 历史记录降级

`best-sentence-practice` 等旧记录可能只有 `words_json`，没有
`source_event_ids_json`。

服务端仍按 `words` 生成 `sourceWords`：

- `traceStatus = "historical"`。
- `word` 保留。
- `sourceLabel = "历史生成"`。
- 答错时间、难度、耗时和答案等追溯字段为 `null`。
- 前端统一显示 `—` 和“无答题来源”。

若外部错题记录声明了事件 ID，但事件已缺失，则使用
`traceStatus = "missing"`，显示“来源记录缺失”，不能降级成“历史生成”掩盖数据
异常。

## API 设计

继续使用现有分页接口：

```text
GET /api/cloze-results/items
```

保留 `ClozeResultItem` 现有字段，新增：

```json
{
  "sourceWords": [
    {
      "word": "fracture",
      "traceStatus": "available",
      "source": "rob_english_word_back",
      "sourceLabel": "难度匹配",
      "sourceEventId": 78,
      "sourceAnswerDetailId": 78,
      "sourceRecordId": 74,
      "sourceWordId": 440,
      "wrongTime": "2026-07-25T12:32:59+08:00",
      "mode": "match",
      "difficultyGroup": "大学英语",
      "difficultyLevel": "",
      "wordDifficulty": 440,
      "answerTimeMs": 1200,
      "selectedAnswer": "",
      "correctAnswer": "fracture"
    }
  ]
}
```

`traceStatus` 只允许：

- `available`：找到完整或部分事件来源。
- `historical`：父记录本来就没有事件链。
- `missing`：父记录引用了事件 ID，但事件不存在或无法对应。

所有可选数字和时间字段使用 `null` 表示未知，不使用 `0` 混淆真实零值。

## 服务端聚合

`ClozeResultApi.Items` 保持以句子表为分页主体，不能按来源单词分页。

每页处理流程：

1. 从 `rob_english_word.sentence_cloze_item` 查询当前页句子。
2. 解码 `words_json` 和四组来源 ID 数组。
3. 收集当前页全部非零 `sourceEventIds`，在
   `select_english_word.wrong_word_events` 中一次批量查询。
4. 对 `rob_english_word_back` 事件，收集答题明细和游戏记录 ID，在
   `rob_english_word` 中一次批量查询答题耗时、模式和难度。
5. 对 `sentence_cloze_practice` 事件，按现有
   `recordId * 1000 + wrongIndex + 1` 契约解析答题记录 ID，并批量读取答题耗时；
   解析失败只降级该单词的可选字段。
6. 以事件 ID 为主键建立映射，按父记录数组顺序组装 `sourceWords`。
7. 无事件链的记录按 `words` 生成历史降级项。

单页请求固定为：

- 1 次句子列表查询。
- 0 或 1 次错词事件批量查询。
- 0 或 1 次游戏答题批量查询。
- 0 或 1 次挖空答题批量查询。

禁止按句子或单词循环查询，避免 N+1。

四组来源 ID 数组与 `words` 应按相同索引对应。若长度不一致：

- 仍为每个 `word` 返回一项。
- 只绑定该索引上存在且有效的 ID。
- 不把后续 ID 左移补位，避免来源错配。
- 将无法绑定的项标为 `missing`，并在服务端记录不含用户答案正文的告警。

## 前端组件

`ClozeResultsPage` 增加 `expandedResultIds: Set<number>`，句子 ID 是唯一展开键。

建议在当前文件内先抽出三个小组件，避免继续扩大页面主体：

- `ClozeResultRow`：主行及展开交互。
- `ClozeResultDetail`：挖空句和中文解释。
- `ClozeSourceWordTable`：来源单词表及降级文案。

TypeScript 的 `ClozeResultItem` 增加 `sourceWords`，并定义
`ClozeResultSourceWord`。前端不根据平行 ID 数组再次组装来源，服务端返回值是
唯一显示契约。

搜索、用户筛选和分页接口不变。搜索仍匹配单词、句子和翻译；本次不扩展为按
事件 ID 搜索。

## 错误处理

- 主句查询失败：沿用当前整表错误状态。
- 来源事件批量查询失败：主句列表仍返回；受影响的词标为 `missing`，接口记录
  脱敏告警。
- 单个游戏或挖空答题记录缺失：保留事件级字段，只把耗时、模式等字段设为
  `null`。
- `words_json` 非法：回退父记录 `word`；两者都为空时显示“未知单词”并记录
  告警。
- 句子、翻译、挖空句或解释为空：前端显示 `—`，不阻止展开。
- 前端收到未知 `traceStatus`：按 `missing` 展示，不能静默当作历史数据。

## 测试策略

### Go 服务端

- 三词外部错题记录返回三个按原顺序排列的 `sourceWords`。
- 游戏事件正确映射模式、难度、耗时、选择答案和正确答案。
- 挖空事件只显示可证明的“挖空练习”，不推断 review/solo。
- 历史无事件记录返回 `historical`。
- 引用不存在事件返回 `missing`。
- 平行数组长度不一致时不发生索引左移或错配。
- 批量聚合查询次数与当前页单词数量无关。
- 原分页总数、用户过滤和关键词过滤保持不变。

### React 前端

- 主行列为最终八列，不再渲染独立单词、挖空句和翻译列。
- 翻译在英文句子下方，长文本具有省略和全文 Tooltip。
- 点击主行和操作文字都可展开/收起，并具有 `aria-expanded`。
- 展开区显示挖空句、解释和来源单词九列。
- 多条句子可同时展开。
- 搜索、切换用户、翻页和改变页大小会清空展开状态。
- `historical` 与 `missing` 使用不同文案。
- 空字段显示 `—`，不会渲染 `0` 或 `undefined` 作为未知值。

### 运行态验收

- 使用包含三词外部错题的用户验证完整追溯。
- 使用 `best-sentence-practice` 历史单词句验证降级。
- 验证搜索、用户筛选和分页后数据与旧页面一致。
- 在 6016 宽屏与较窄窗口检查主行可读性、展开区横向滚动和键盘操作。
- 只读核对接口展示，不修改错词事件或句子数据。

## 已选方案总结

- 视觉方案：A，句子主行 + 来源单词展开。
- 详情位置：A1，翻译跟随主句；挖空句和解释位于展开区。
- 覆盖范围：B1，全部来源记录统一布局，历史数据明确降级。
- 技术方案：服务端批量聚合嵌套 `sourceWords`，不改表、不做前端二次请求。
