# 7002 难度选择关闭流程设计（最终确认版）

## 背景

`HomeView` 内存在两层训练界面：难度训练设置页，以及覆盖在其上的难度选择页。当前两个界面分别关闭各自状态，因此用户从难度选择页退出时，会先看到难度训练页及第二个叉号，还需再次关闭才能回主页。

用户于 2026-07-19 最终确认：难度选择页的显式关闭只关闭选择覆盖层，返回难度训练设置页；随后关闭难度训练设置页才返回主页。

## 目标行为

| 当前界面 | 右上角叉号 / Escape 的目标 | 页面内正常操作 |
| --- | --- | --- |
| 难度训练 | 主页 | 各按钮行为不变 |
| 难度选择 | 难度训练，只关闭难度选择层 | 选中具体难度仍返回难度训练页 |
| 今日答题结果 | 难度训练 | 列表操作不变 |
| 已掌握单词 | 难度训练 | 搜索、筛选和分页不变 |
| 错题详情 | 错题列表 | 不变 |
| 记录详情 | 记录列表 | 不变 |

## 实现方案

- 保留 `closeTrainingSetup()`，负责关闭难度训练页。
- 使用 `closeDifficultyPicker()` 只清除 `showDifficultyPicker`。
- 难度选择页的叉号绑定 `closeDifficultyPicker()`；难度训练页的叉号继续绑定 `closeTrainingSetup()`。
- 难度选择覆盖层必须建立在共享叉号的 `z-index` 之上，避免两个同位置叉号重叠时点击落到底层控件。
- Escape 在难度选择页可见时调用 `closeDifficultyPicker()`，保证键盘关闭和按钮关闭一致。
- `selectDifficulty()` 与 `selectRankDifficulty()` 仍只关闭难度选择层，用户完成选择后继续停留在难度训练页。
- 今日答题结果、已掌握单词及其他详情页不纳入本次行为修改。

## 测试方案

1. 先写组件级和状态级回归测试，验证难度选择叉号关闭后难度训练仍可见。
2. 实施最小状态修改后验证 GREEN。
3. 保留选中难度后返回难度训练的测试，防止显式关闭与正常选择混淆。
4. 运行完整 Vitest、Vite 生产构建和 `git diff --check`。
5. 在登录后的 7002 真实浏览器中点击顶层叉号，确认一次点击后返回难度训练页。

## 非目标

- 不修改按钮文案、样式、布局或动画。
- 不改变匹配、单人训练和难度保存逻辑。
- 不把答题结果、已掌握单词或详情页改成直接回主页。
