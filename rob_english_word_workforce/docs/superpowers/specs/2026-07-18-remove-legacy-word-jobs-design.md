# 删除旧造句、评分和 TTS 任务功能设计

## 背景

造句、评分和 TTS 批处理任务已经迁移到任务中心。本仓库不再保留旧 Dashboard 中的三个任务管理页面、对应的 Go API，以及 `word-agent` 中对应的批处理任务实现。

本次只移除三类批处理任务能力。`word-agent` 的在线造句、单次评分、单次 TTS、错词事件和其他通用能力继续保留。

## 删除范围

### React 管理端

- 删除“造句任务表”“评分任务表”“TTS 任务表”三个菜单项。
- 删除三个页面组件、页面状态和页面渲染分支。
- 删除页面专用的 API 客户端函数、类型、常量和 CSS。
- 删除仅由旧评分任务页面使用的评分提示词预览与评分结果导入交互。

### Go 服务

- 删除三类任务的列表与启动路由。
- 删除评分任务预览及评分结果导入路由。
- 删除对应 handler、请求/响应类型、查询条件、建表辅助函数和调用 Python job 接口的代理函数。
- 删除只覆盖上述旧接口的测试。
- 保留句子、评分结果、最佳句子和音频业务字段及其正常业务接口。

### Python `word-agent`

- 删除三个批处理 job 的 HTTP 路由、后台执行函数及并发锁。
- 删除批处理 job 专用 schema、service、辅助脚本和测试。
- 删除只被这些 job 使用的配置或依赖；如仍被通用在线能力使用则保留。
- 保留在线造句、单次评分、单次 TTS、音频下载、错词事件和通用 run 执行能力。

### 数据库

删除以下表及全部历史任务数据：

- `word_clean_sentence_job`
- `word_clean_sentence_score_job`
- `word_clean_sentence_tts_job`

不删除以下业务成果：

- 已生成的句子及翻译；
- 已写入的评分和最佳句子数据；
- 已生成的音频文件、音频业务字段和 MinIO 对象；
- 其他词库及用户业务数据。

删表使用显式表名并在执行前确认目标数据库。删除顺序先移除应用代码引用，再执行 `DROP TABLE IF EXISTS`。不使用级联删除，避免意外删除关联业务对象。

## 启动与文档调整

- `word-agent` 服务本身仍由统一启动脚本启动，端口和通用配置保持不变。
- 删除项目文档中关于三个旧任务页面、接口和任务表的说明。
- 不修改任务中心仓库或外部系统。

## 测试与验收

实施采用删除行为测试先行：先增加会因旧入口仍存在而失败的检查，再删除代码使检查通过。

验收条件：

1. 管理端不再显示三个菜单，也不存在对应页面分支或 API 客户端。
2. Go 路由不再暴露三类任务管理、评分预览和评分导入接口。
3. `word-agent` 不再暴露三个批处理 job 路由，且不包含对应 job service/schema。
4. 三个任务表在目标数据库中不存在，其他业务表和成果数据仍存在。
5. React 构建、Go 测试和 Python 测试通过。
6. 全仓库残留引用检查仅允许历史设计文档中出现旧名称；运行时代码、启动脚本和现行说明中不得残留。
7. 统一启动脚本能够启动其余全部服务，保留的 `word-agent` 通用健康检查正常。

## 风险控制

- 删除任务表是不可恢复的数据操作；执行前仅核对表名和目标数据库，不触碰成果表。
- Go 文件中任务代码与词库业务代码共存，删除时以符号和引用为边界，不重写无关逻辑。
- Python 通用能力与 job 能力共享 LLM、TTS 和存储服务；共享模块按引用关系保留。
- 若删除后测试暴露共享依赖，恢复共享部分，而不是恢复旧 job 入口。
