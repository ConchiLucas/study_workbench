# 错题集例句展示与目标词高亮设计

## 目标

在用户端 `/wrong-words` 错题集表格中增加“例句”列，帮助用户在语境中复习每个待复习错词。

每个错词只展示该词经评分选出的 AI 最佳例句，不使用原词库例句作为回退。例句中的目标单词或词组使用当前页面的紫色主题高亮。

## 已确认需求

- 在现有错题集表格中增加独立“例句”列。
- 只展示英文例句，不展示中文翻译。
- 例句只使用 `word_clean_best_sentence.sentence`。
- 最佳例句不存在或为空时显示 `—`，不回退 `word.sentence`。
- 高亮目标单词时忽略大小写，并支持带空格的词组。
- 不能把较长单词内部的相似子串错误高亮。
- 沿用现有 `/api/wrong-words/events`，不增加前端逐词请求。

## 非目标

- 不生成或修改例句。
- 不修改错词复习阶段、排序、分页和完成口径。
- 不把例句纳入搜索范围。
- 不显示例句中文翻译、模型名称、评分或来源标签。
- 不修改数据库表结构或迁移现有数据。
- 不修改管理后台词库管理页面。

## 方案选择

### 方案一：现有错题查询直接返回例句

在 `WrongWordQueueEventSqlProvider` 的现有分页查询中只关联 AI 最佳例句，接口直接返回最终例句。

优点是一次请求完成、分页稳定、前端契约简单，也不会产生 N+1 请求。采用此方案。

### 方案二：Java 服务层批量补充例句

先查询错词分页，再收集单词 ID 和英文内容批量查询例句。

该方案能降低主 SQL 复杂度，但需要新增服务层组装、批量映射和额外查询，当前需求没有足够收益，不采用。

### 方案三：前端逐词请求例句

前端拿到错词列表后逐行请求例句。

该方案会让每页产生 20 至 500 次额外请求，加载状态和失败处理也更复杂，不采用。

## 数据与接口设计

继续使用：

```text
GET /api/wrong-words/events
```

`WrongWordQueueEvent` 增加：

```json
{
  "exampleSentence": "The team gained momentum after the first success.",
  "exampleSource": "best_sentence"
}
```

字段语义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `exampleSentence` | `string \| null` | AI 最佳英文例句 |
| `exampleSource` | `best_sentence \| none` | 例句来源，供契约测试和后续诊断使用 |

当前页面不展示 `exampleSource`。保留该字段是为了区分最佳例句正常命中和缺失，避免前端根据内容猜测来源。

## 例句选择规则

对 `active_words` 中的每条未完成错词：

1. 按 `wrong_word_review_progress.normalized_word` 匹配
   `LOWER(BTRIM(word_clean_best_sentence.word))`。
2. 只接受去除首尾空格后仍非空的 `sentence`。
3. 命中时返回最佳例句，来源为 `best_sentence`。
4. 未命中时返回 `null`，来源为 `none`。
5. 不查询 `word.sentence`，也不根据 `word_id` 选择原词库例句。

查询使用 `LEFT JOIN LATERAL` 或等价单行子查询，并按最佳句记录 `id`
确定性选择一条。每个错词最多产生一条结果，不能改变当前分页总数和行数。

## 前端布局

桌面表格列顺序改为：

```text
来源单词｜例句｜答错时间｜入口 / 模式｜词库 / 难度｜词难度｜耗时｜正确答案
```

例句列规则：

- 最多显示两行，超出部分省略。
- `title` 或等价可访问提示展示完整例句。
- 空值显示 `—`。
- 例句列给予最大的弹性宽度；时间、词难度和耗时保持紧凑。
- 较窄屏幕继续使用现有卡片布局，“例句”通过 `data-label` 作为独立字段显示，不让整页产生横向滚动。

加载骨架、空状态、排序、分页和搜索交互保持不变。

## 目标词高亮

前端新增纯函数：

```text
splitHighlightedSentence(sentence, word)
```

返回按原顺序排列的文本片段，每个片段包含文本和是否高亮。模板使用 Vue 文本插值和条件 class 渲染，禁止使用 `v-html`。

匹配规则：

- 忽略大小写，但保留例句原始大小写。
- 对目标词中的正则特殊字符进行转义。
- 支持带空格的词组。
- 目标词首尾是英文字母或数字时，匹配位置两侧不能继续是英文字母或数字。
- 高亮例句中的全部合法出现位置。
- 找不到合法匹配时，显示完整例句但不高亮。

边界示例：

- `momentum` 可以高亮 `The team gained momentum quickly.`
- `Word` 可以高亮 `This word is useful.`
- `make a mistake` 可以作为完整词组高亮。
- `raw` 不能高亮 `draw` 中的 `raw`。

高亮样式使用紫色文字、半粗体和轻微紫色背景，不改变行高，也不能仅依靠颜色表达内容。

## 错误与降级处理

- AI 最佳例句缺失：接口仍返回错词，例句为 `null`，不使用原词库例句。
- 例句只有空白字符：按缺失处理。
- 目标词为空：不高亮，但仍安全展示例句。
- 例句不包含目标词：展示完整例句，不尝试词干推断或模糊匹配。
- 例句关联查询失败：按接口整体数据库错误处理，不吞掉真实数据库故障；单纯无匹配不是错误。

## 测试策略

### Java

- DTO 包含 `exampleSentence` 和 `exampleSource`。
- SQL 只关联 `word_clean_best_sentence`。
- 最佳例句存在时返回 `best_sentence`。
- 最佳例句为空或不存在时返回 `none` 和空例句。
- SQL 不包含 `word.sentence` 选择或原词库例句回退。
- 关联例句后错词总数、排序和分页语义保持不变。

### Vue

- 表头和每行都渲染“例句”字段。
- 普通单词、大小写变体和多词短语正确高亮。
- 相似子串不被误高亮。
- 正则特殊字符不会造成运行时错误。
- 无匹配时完整显示原例句。
- 空例句显示 `—`。
- 渲染不使用 `v-html`。
- 小屏卡片保留例句标签。

### 回归与运行态

- Java 相关合同测试和完整测试通过。
- 用户端相关单元测试、完整测试和生产构建通过。
- 使用存在 AI 最佳例句和完全无最佳例句的错词各验证一条。
- 非 Docker 重启后访问 `/wrong-words`，确认例句列、高亮、分页和窄屏布局正常。

## 最终范围

本功能只扩展用户错题集的读取和展示契约。它不改变例句数据、不改变复习进度，也不影响管理后台和挖空练习页面。
