# 儿童学习工作台（家长版）技术方案

> 版本 v1 · 2026-08-21 · 目标：面向家长的「学习情况看板」后台，前后端一体。答题（做题）界面在后续版本扩充，本版只预留接口与数据结构。

---

## 1. 目标与非目标

### 本版要做的
1. **家长端看板**：一眼看出孩子「哪些学会了、哪些没学会、哪些快忘了、哪些一直错」。
2. **知识点级别的掌握度模型**：掌握状态不是靠人工勾选，而是由作答记录自动推导（同时保留家长手动标记）。
3. **后端 API + 数据库**：一套稳定的读模型（看板查询）与写入口（作答上报），供未来答题端直接复用。
4. **保留原型的菜单结构**：识字 / 拼音 / 算术 / 英语 / 科普 / 古诗 / 逻辑 / 游戏 / 任务打卡 / 奖励商店。内容形态改成「掌握情况」而不是「答题卡片」。

### 本版不做（YAGNI）
- 答题界面、语音识别、TTS 读题（只建表、留接口）。
- 多租户 / 机构版 / 班级管理。
- 推荐算法、AI 出题、个性化学习路径（先把数据积累起来）。
- 小程序端。先做响应式 Web（iPad 横屏优先，兼容手机竖屏）。

---

## 2. 核心设计思路：把「答题工作台」翻转成「掌握度工作台」

原型的信息单元是**一道题**（2+5=? → 我来答 → 学会了）。家长版的信息单元要换成**一个知识点的掌握状态**。

三层内容骨架：

```
学科 Subject        识字 / 拼音 / 算术 / 英语 / 科普 / 古诗 / 逻辑 / 游戏
  └─ 模块 Module     认数字 / 10以内加法 / 10以内减法 / 比大小 / 认识图形
       └─ 知识点 KnowledgePoint   "2+5"  "7-3"  汉字"月"  拼音"zh"  古诗《静夜思》
```

**知识点是掌握度的最小单元**，也是页面上那一个个小方块。一个知识点下面挂多道题（未来答题端用），题目答对答错回流成知识点的掌握状态。

### 五种掌握状态（贯穿全系统的语义）

| 状态 | code | 颜色 | 家长看到的含义 |
|---|---|---|---|
| 未开始 | `not_started` | 浅灰 | 还没练过 |
| 学习中 | `learning` | 黄 | 练过但还不稳 |
| 需巩固 | `shaky` | 橙红 | 反复出错，重点关注 |
| 已掌握 | `mastered` | 绿 | 连续答对，稳了 |
| 待复习 | `review_due` | 蓝 | 曾掌握，到复习点了（防遗忘） |

`review_due` 是**派生状态**：库里 `status = mastered` 且 `due_at < now()`，查询时判定。这样避免全表定时改写。

## 3. 页面设计（家长端 5 个页面）

保留左侧学科菜单，右侧内容全部换成掌握情况。

### 3.1 总览页 `/`（默认页，最重要）

自上而下四块：

**① 四张大数字卡**
```
已掌握 128        学习中 46        需巩固 12        待复习 9
本周 +15 ↑        —                需要陪练          今天该复习
```
配一个总进度环：`128 / 668`（全部知识点）。

**② 学科掌握矩阵（本方案的主视觉）**

每个学科一行，行内每个小方块 = 一个知识点，按模块分组，颜色即状态。这是「直观展示哪些学会哪些没学会」的核心组件。

```
算术  认数字 ■■■■■■■■□□   10以内加法 ■■■■□□□□▨▨▨▨...  10以内减法 □□□□...
      ■ 已掌握  ▨ 需巩固  ▧ 学习中  □ 未开始  ▩ 待复习
识字  声母 ■■■■■■▨□...   韵母 ...
```
- hover 显示知识点名称 + 正确率；点击打开右侧详情抽屉。
- 知识点多的学科（识字 100+）按模块折叠，默认只展开有进度的模块。

**③ 学习趋势（近 30 天）**

双轴面积图 + 柱图：柱 = 每日练习时长（分钟），面积 = 累计已掌握数。让家长看到「掌握曲线在往上走」。

**④ 需要关注 Top 10**

按 `错误次数 × 最近出错时间` 排序的知识点列表，每行：知识点名 · 正确率进度条 · 错了几次 · 「加入今日复习」按钮。

### 3.2 学科详情页 `/subjects/:code`

左侧菜单点进来的页面。头部圆环（该学科掌握率 + 本周新增），下面按模块列出知识点卡片网格，支持按状态筛选（只看没学会的 / 只看需巩固的）。

### 3.3 需要关注页 `/attention`

`shaky` + `review_due` 全量列表，可按学科过滤，是家长「今天陪练什么」的答案页。

### 3.4 学习日历 `/calendar`

GitHub 贡献图风格的热力日历（按练习时长着色）+ 连续打卡天数 + 任务打卡完成情况。对应原型的「任务打卡」菜单。

### 3.5 知识点详情抽屉（全局组件）

从任意方块点开：当前状态、正确率曲线、每次作答明细（对/错/耗时/来源）、下次复习时间、「标记为已学会 / 撤销」按钮。

### 3.6 保留但轻量的两个菜单
- **奖励商店**：小红花余额 + 流水 + 奖励兑换列表（简单 CRUD）。
- **游戏**：本版按普通学科处理（知识点=游戏关卡），不做游戏逻辑。

## 4. 掌握度引擎（后端最核心的一块）

### 4.1 输入输出

纯函数，无 IO，方便单测：

```go
// internal/mastery/engine.go
package mastery

type Status string

const (
    StatusNotStarted Status = "not_started"
    StatusLearning   Status = "learning"
    StatusShaky      Status = "shaky"
    StatusMastered   Status = "mastered"
)

// State 与 mastery_states 表一一对应
type State struct {
    Status        Status
    Attempts      int
    Correct       int
    Streak        int       // 当前连续答对
    BestStreak    int
    Ease          float64   // 难度因子 1.3 ~ 2.8
    IntervalDays  int
    DueAt         time.Time
    FirstSeenAt   time.Time
    MasteredAt    *time.Time
}

type Attempt struct {
    Correct bool
    At      time.Time
    Source  string // quiz | parent_mark | game
}

// Apply 返回新状态，不修改入参
func Apply(s State, a Attempt, kpDifficulty int) State
```

### 4.2 规则（简化 SM-2 间隔重复）

```
accuracy = Correct / Attempts
masterStreak = 2 + kpDifficulty   // 难度 1~3 → 需要连对 3~5 次

答对：
  Streak++；Ease = min(2.8, Ease + 0.1)
  若 Streak >= masterStreak 且 accuracy >= 0.8：
      Status = mastered
      IntervalDays = nextInterval(IntervalDays, Ease)   // 1 → 3 → 7 → 15 → 30（上限 60）
      DueAt = at + IntervalDays
      MasteredAt 首次置位
  否则：
      Status = learning；IntervalDays = 1；DueAt = at + 1d

答错：
  Streak = 0；Ease = max(1.3, Ease - 0.2)
  IntervalDays = 1；DueAt = at + 1d
  若 Attempts >= 3 且 accuracy < 0.6 → Status = shaky
  否则 → Status = learning
  （原本 mastered 的知识点答错会掉回 learning/shaky，符合家长直觉）

家长手动标记（source = parent_mark）：
  直接 Status = mastered，Streak = max(Streak, masterStreak)，IntervalDays = 3
  记一条 attempt 留痕，可撤销（撤销 = 重放该知识点的历史 attempts）
```

### 4.3 待复习判定（查询期）

```sql
CASE WHEN status = 'mastered' AND due_at < now() THEN 'review_due' ELSE status END
```

### 4.4 单元测试清单（TDD 先写这些）
- 连对 3 次 → mastered，interval=1
- mastered 后再答对 → interval 递增，due_at 推后
- mastered 后答错 → 回落 learning，streak=0
- 5 次里错 3 次 → shaky
- ease 上下界收敛
- 手动标记 → mastered 且可撤销后回到原状态

## 5. 数据模型

v1 用 **SQLite**（家庭单机场景足够，单文件好备份），迁移用自研的轻量 runner（读 embed 的 `.sql` 按文件名顺序执行，`schema_migrations` 表记录版本）。

下面的 DDL 用 Postgres 方言书写，作为**逻辑参考**——字段、约束、索引以此为准。落地的 SQLite 版 DDL 见实施计划 Task 2（`BIGSERIAL` → `INTEGER PRIMARY KEY AUTOINCREMENT`、`JSONB` → `TEXT`、`TIMESTAMPTZ` → `DATETIME`、`BOOLEAN` → `INTEGER`）。未来迁 Postgres 时直接启用这份 DDL。

```sql
-- 家长账号
CREATE TABLE users (
  id          BIGSERIAL PRIMARY KEY,
  phone       VARCHAR(20) UNIQUE NOT NULL,
  nickname    VARCHAR(50),
  password_hash VARCHAR(100) NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE children (
  id         BIGSERIAL PRIMARY KEY,
  name       VARCHAR(50) NOT NULL,       -- 柯沐沐
  grade      VARCHAR(20),                -- 大班
  avatar_url VARCHAR(255),
  birthday   DATE,
  flowers    INT NOT NULL DEFAULT 0,     -- 小红花余额
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE parent_child (
  user_id  BIGINT NOT NULL REFERENCES users(id),
  child_id BIGINT NOT NULL REFERENCES children(id),
  relation VARCHAR(20),                  -- 妈妈/爸爸
  role     VARCHAR(20) NOT NULL DEFAULT 'owner', -- owner | viewer
  PRIMARY KEY (user_id, child_id)
);

-- ============ 内容目录（全局共享，不按孩子） ============
CREATE TABLE subjects (
  id       BIGSERIAL PRIMARY KEY,
  code     VARCHAR(30) UNIQUE NOT NULL,  -- literacy/pinyin/math/english/science/poem/logic/game
  name     VARCHAR(30) NOT NULL,         -- 识字/拼音/算术...
  icon     VARCHAR(20),
  order_no INT NOT NULL DEFAULT 0
);

CREATE TABLE modules (
  id         BIGSERIAL PRIMARY KEY,
  subject_id BIGINT NOT NULL REFERENCES subjects(id),
  code       VARCHAR(50) NOT NULL,
  name       VARCHAR(50) NOT NULL,       -- 10以内加法
  order_no   INT NOT NULL DEFAULT 0,
  UNIQUE (subject_id, code)
);

CREATE TABLE knowledge_points (
  id         BIGSERIAL PRIMARY KEY,
  module_id  BIGINT NOT NULL REFERENCES modules(id),
  code       VARCHAR(80) NOT NULL,       -- math.add10.2p5
  title      VARCHAR(80) NOT NULL,       -- 2+5
  payload    JSONB,                      -- 展示用：{"a":2,"b":5,"emoji":"🍎"}
  difficulty SMALLINT NOT NULL DEFAULT 1,-- 1~3
  order_no   INT NOT NULL DEFAULT 0,
  UNIQUE (module_id, code)
);

-- 题目：本版只建表 + 少量种子，答题端使用
CREATE TABLE questions (
  id        BIGSERIAL PRIMARY KEY,
  kp_id     BIGINT NOT NULL REFERENCES knowledge_points(id),
  type      VARCHAR(20) NOT NULL,        -- choice | input | voice | order
  stem      TEXT NOT NULL,
  options   JSONB,
  answer    JSONB NOT NULL,
  media_url VARCHAR(255),
  difficulty SMALLINT NOT NULL DEFAULT 1
);

-- ============ 学习事实与聚合 ============
CREATE TABLE attempts (                  -- 事实表，只追加
  id           BIGSERIAL PRIMARY KEY,
  child_id     BIGINT NOT NULL REFERENCES children(id),
  kp_id        BIGINT NOT NULL REFERENCES knowledge_points(id),
  question_id  BIGINT REFERENCES questions(id),
  is_correct   BOOLEAN NOT NULL,
  cost_ms      INT NOT NULL DEFAULT 0,
  source       VARCHAR(20) NOT NULL,     -- quiz | parent_mark | game
  client_id    VARCHAR(64),              -- 幂等键，答题端生成
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (child_id, client_id)
);
CREATE INDEX idx_attempts_child_kp_time ON attempts(child_id, kp_id, created_at DESC);

CREATE TABLE mastery_states (            -- 聚合表，读模型主表
  child_id      BIGINT NOT NULL REFERENCES children(id),
  kp_id         BIGINT NOT NULL REFERENCES knowledge_points(id),
  status        VARCHAR(20) NOT NULL,
  attempts      INT NOT NULL DEFAULT 0,
  correct       INT NOT NULL DEFAULT 0,
  streak        INT NOT NULL DEFAULT 0,
  best_streak   INT NOT NULL DEFAULT 0,
  ease          REAL NOT NULL DEFAULT 2.5,
  interval_days INT NOT NULL DEFAULT 0,
  due_at        TIMESTAMPTZ,
  first_seen_at TIMESTAMPTZ,
  mastered_at   TIMESTAMPTZ,
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (child_id, kp_id)
);
CREATE INDEX idx_mastery_child_status ON mastery_states(child_id, status);
CREATE INDEX idx_mastery_due ON mastery_states(child_id, due_at);

CREATE TABLE study_sessions (            -- 学习时长
  id         BIGSERIAL PRIMARY KEY,
  child_id   BIGINT NOT NULL,
  subject_id BIGINT,
  started_at TIMESTAMPTZ NOT NULL,
  ended_at   TIMESTAMPTZ,
  duration_sec INT NOT NULL DEFAULT 0
);

CREATE TABLE daily_stats (               -- 预聚合，趋势/日历直接查
  child_id        BIGINT NOT NULL,
  stat_date       DATE NOT NULL,
  practice_sec    INT NOT NULL DEFAULT 0,
  attempts        INT NOT NULL DEFAULT 0,
  correct         INT NOT NULL DEFAULT 0,
  newly_mastered  INT NOT NULL DEFAULT 0,
  review_done     INT NOT NULL DEFAULT 0,
  checked_in      BOOLEAN NOT NULL DEFAULT false,
  PRIMARY KEY (child_id, stat_date)
);

-- ============ 任务打卡 & 奖励 ============
CREATE TABLE daily_tasks (
  id           BIGSERIAL PRIMARY KEY,
  child_id     BIGINT NOT NULL,
  task_date    DATE NOT NULL,
  title        VARCHAR(80) NOT NULL,     -- 练 5 个算术知识点
  subject_id   BIGINT,
  target_count INT NOT NULL DEFAULT 1,
  done_count   INT NOT NULL DEFAULT 0,
  reward_flowers INT NOT NULL DEFAULT 1,
  status       VARCHAR(20) NOT NULL DEFAULT 'pending' -- pending|done
);

CREATE TABLE rewards (
  id       BIGSERIAL PRIMARY KEY,
  child_id BIGINT NOT NULL,
  name     VARCHAR(50) NOT NULL,
  cost     INT NOT NULL,
  stock    INT NOT NULL DEFAULT 1
);

CREATE TABLE flower_ledger (
  id        BIGSERIAL PRIMARY KEY,
  child_id  BIGINT NOT NULL,
  delta     INT NOT NULL,
  reason    VARCHAR(50) NOT NULL,        -- task_done | mastered | redeem
  ref_type  VARCHAR(20),
  ref_id    BIGINT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 写入链路（唯一入口）

```
POST /attempts
  → 幂等校验 (child_id, client_id)
  → 事务：insert attempts
         → 读 mastery_states 行（行锁）
         → mastery.Apply() 纯函数算新状态
         → upsert mastery_states
         → upsert daily_stats（attempts/correct/newly_mastered 增量）
         → 若新掌握：flower_ledger +1，children.flowers 累加
  → 返回新的掌握状态给客户端（答题端可即时展示"学会了！"）
```

家长手动标记走同一条链路，只是 `source = parent_mark`。**所有掌握度变化都可由 attempts 重放复现**，这是数据可信的基础。

## 6. API 设计

统一前缀 `/api/v1`，响应包 `{ "data": ..., "error": null }`。

v1 免登录：`middleware.CurrentUser` 直接注入 `userID = 1`，接口签名与 M7 加 JWT 后完全一致，所以 handler 层不需要为鉴权改动。

### 基础
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/me` | 当前家长 + 关联孩子列表（v1 返回固定用户） |
| POST | `/auth/login` | M7 补齐，v1 不实现 |

### 看板读接口（本版重点）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/children/:cid/overview` | 四张卡 + 总进度 + 本周变化 |
| GET | `/children/:cid/subjects` | 各学科掌握率汇总（左侧菜单 + 学科卡） |
| GET | `/children/:cid/mastery/matrix?subject=math` | **掌握矩阵**，按模块分组返回知识点+状态 |
| GET | `/children/:cid/knowledge-points?status=shaky&subject=math&page=1` | 知识点筛选列表 |
| GET | `/children/:cid/knowledge-points/:kpId` | 详情抽屉：状态 + 作答历史 |
| GET | `/children/:cid/stats/trend?days=30` | 趋势图数据 |
| GET | `/children/:cid/stats/calendar?months=3` | 日历热力图 |
| GET | `/children/:cid/attention?limit=10` | 需要关注 Top N |

> 周报（`/report/weekly`）挪到 v2：overview 的 `week_delta` 加上趋势图已经能回答「这周进步了多少」，专门的周报页在有真实使用数据后再做。

### 写接口
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/children/:cid/attempts` | **批量上报作答（答题端未来唯一写入口）** |
| POST | `/children/:cid/knowledge-points/:kpId/mark` | 家长手动标记 `{status:"mastered"}` |
| DELETE | `/children/:cid/knowledge-points/:kpId/mark` | 撤销手动标记（重放历史） |
| POST | `/children/:cid/tasks` / PATCH `/tasks/:id` | 任务打卡 |
| POST | `/children/:cid/rewards/:id/redeem` | 兑换奖励 |

### 为答题端预留
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/children/:cid/review-queue?limit=20` | 今日该练的知识点（due_at 到期 + shaky 优先） |
| GET | `/knowledge-points/:kpId/questions` | 取题 |

## 11. 风险与取舍

1. **早期数据稀疏**：孩子刚用时全是 `not_started`，看板显得空。对策：种子 demo 数据 + 首屏文案引导「先做 5 个知识点」。
2. **掌握判定阈值需要调**：`masterStreak`、`accuracy` 阈值先写死在配置里（`config.Mastery`），后续按真实数据调整，不改代码。
3. **`daily_stats` 与 attempts 可能漂移**：提供 `make recompute --child=1` 重放 attempts 重建聚合表，作为兜底。
4. **知识点粒度过细**（英语 200、识字 100）：矩阵页需要虚拟滚动或模块折叠，否则一屏几百个 DOM。M4 就按模块折叠实现。
5. **家长手动标记会污染数据**：标记单独记 source，统计口径里可区分「练出来的掌握」和「家长认定的掌握」。

## 12. 已确认的决策（2026-08-21）

1. **技术栈**：后端 Go + Gin + GORM，前端 React 18 + TS + Vite + Tailwind + ECharts。
2. **登录**：v1 免登录单用户模式。中间件层注入固定的 `currentUserID = 1`，`users` / `parent_child` 表照建但不校验密码；M7 再接 JWT，届时只改中间件，handler 与 service 不动。
3. **知识点粒度**：单题级，共 668 个知识点，内容用生成脚本产出（算术/拼音/古诗按规则生成，识字/英语/科普用词表）。
