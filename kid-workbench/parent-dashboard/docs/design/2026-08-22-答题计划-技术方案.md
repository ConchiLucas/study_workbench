# 每日答题计划 + iPad 答题端 技术方案

> 版本 v1 · 2026-08-22 · 前置：`docs/design/2026-08-21-学习工作台-技术方案.md`（家长看板已上线）
> 目标：孩子用 iPad 打开网页，每天完成一个「刚好合适」的练习计划，作答结果自动回流到家长看板的掌握度。

---

## 1. 范围

### 做
1. **每日答题计划**：系统每天为孩子生成一份 10 题的练习单，内容由掌握度决定（该复习什么、哪里老错、可以学点新的）。
2. **iPad 答题端**：独立路由 `/kid`，一题一屏、大按钮、语音读题、零打字，5 岁孩子能自己操作。
3. **题库自动生成**：从已有的 668 个知识点批量生成选择题，灌进 `questions` 表。
4. **结算与奖励**：完成计划给星星和小红花，接上已有的 `flower_ledger`。

### 不做（YAGNI）
- 手写识别、语音答题（跟读打分）。
- 家长自定义组卷（v1 计划全自动，只给「再来一组」按钮）。
- 多孩子切换、离线缓存作答（iPad 家用场景在线即可，但作答接口已幂等，v2 加离线补传成本很低）。

## 2. 5 岁孩子的量化设计（这版最关键的约束）

大班孩子（5~6 岁）的注意力窗口大约 **8~12 分钟**，超过就开始扭动、乱点。所有参数围绕这个来定：

| 项 | 取值 | 理由 |
|---|---|---|
| 每个计划题量 | **10 题** | 每题含读题、思考、点选约 30~45 秒，总时长 6~8 分钟，留出缓冲不超 10 分钟 |
| 每天计划数 | **1 个主计划**（可选 1 次「再来一组」） | 一天核心任务只有一件，完成即闭环；想多练由家长点加餐 |
| 单题超时 | 不限时，但 20 秒后自动重播读题 | 计时会给孩子压力，这个年龄不适合 |
| 错题处理 | 当场「再试一次」，第二次仍错则给答案并跳过 | 立刻纠正比事后复习有效；不追第三次以免挫败 |
| 题型 | 只有**四选一**（点图/点字/点数字） | 零打字，手指点得到；选项 2×2 大格排布 |
| 反馈 | 每题即时对错 + 音效 | 延迟反馈对这个年龄基本无效 |
| 不展示 | 正确率、排名、倒计时 | 家长看数据，孩子只看星星 |

**选项数为什么是 4 而不是 3 或 6**：3 个选项猜中概率 33%，掌握度信号太噪；6 个选项在 iPad 上单格变小、且超出这个年龄的视觉扫描能力。2×2 布局是手指和眼睛都舒服的平衡点。

结算给 1~3 颗星：10 题里对 9~10 颗三星，7~8 颗两星，其余一星。**一星也是通过**，配文案「今天也很努力」，不出现「失败」状态。

## 3. 每日计划生成算法

### 分桶配额

一份 10 题的计划按掌握状态分配，优先级从上到下：

| 桶 | 来源状态 | 目标题数 | 含义 |
|---|---|---|---|
| 复习 | `review_due` | 4 | 曾掌握、到复习点了，防遗忘 |
| 巩固 | `shaky` | 2 | 反复出错的重点 |
| 进行中 | `learning` | 2 | 练过还不稳，再推一把 |
| 新知 | `not_started` | 2 | 每天学点新的，保持新鲜感 |

**配额不足时顺序补位**：某桶候选不够（比如刚开始用，没有 `review_due`），缺口按 `巩固 → 进行中 → 新知` 依次顶上，保证每天都是满 10 题。反之候选过多则截断，多出来的留到明天。

### 学科轮转

单纯按优先级排，很容易一整个计划都是英语（因为英语知识点最多）。所以加一条约束：**一个计划最多来自 3 个学科，且同一学科不超过 5 题**。实现上按学科分组轮询取题（round-robin），并用 `plan_date` 做种子轮换起始学科，让每天的学科组合不一样。

### 生成时机

**懒生成**：`GET /plans/today` 时，如果当天没有计划就现场生成并落库。不用定时任务——家里的 iPad 不一定每天开机，定时任务反而会造出一堆没人做的空计划。

计划一旦生成就固定下来（题目 ID 都存进 `plan_items`），中途刷新页面、换设备继续，看到的是同一份题，答过的题不会重来。

## 4. 题库：从知识点自动出题

`questions` 表现在是空的。不手写题目，为每个学科写一个生成器，从知识点的 `title` 和 `payload` 推出题面与干扰项。

### v1 支持的学科（443 个知识点可出题）

| 学科 | 可出题数 | 题型设计 | 干扰项策略 |
|---|---|---|---|
| 算术 · 认数字 | 10 | 「听数字，点出来」（🔊「三」→ 选 3） | 相邻数字 ±1、±2 |
| 算术 · 加减法 | 50 | 🍎🍎 + 🍎🍎🍎 与 `2+3=?` 同屏 | 正确答案 ±1、±2、±3 |
| 算术 · 认识图形 | 8 | 「点出圆形」→ 4 个 emoji 图形 | 其他图形 emoji |
| 拼音 | 45 | 🔊 读音 → 点出对应字母 | 同组易混（b/d/p/q、an/ang） |
| 识字 | 130 | 🔊 读字音 → 点出汉字 | 同组内其他字（字形/读音接近） |
| 英语 | 200 | 🔊 读单词 → 点出中文/emoji；或中文 → 点英文 | 同话题内其他单词 |

**干扰项必须"像"**，随机抽会让孩子靠排除法蒙对，掌握度就失真了。所以数字题用邻近数、拼音用形近字母、词汇用同话题词。

### v1 暂不出题的学科

科普（99）、逻辑（62）、古诗（50）、游戏（8），共 219 个知识点。它们的 `title` 是「规律题 1」「静夜思」这类占位，自动生成不出有意义的题面，需要真实内容库。

这些知识点 **不进入答题计划**（生成时按学科白名单过滤），但仍然：
- 在家长看板正常显示状态
- 支持家长手动标记「学会了」

`subjects` 表加一列 `quiz_enabled BOOLEAN`，白名单落在数据里而不是写死在代码里，将来补齐内容只改一行数据。

### 生成方式

一次性 CLI：`go run ./cmd/seed -mode=questions`，幂等（按 `kp_id + type` 去重）。每个知识点生成 1~3 道变体（同一知识点换不同问法/不同干扰项组合），让孩子第二次遇到时不是完全相同的题，避免背答案位置。

## 5. 数据模型

复用现有 `questions` / `attempts` / `mastery_states` / `flower_ledger`，新增两张表。

```sql
-- 每日计划（一个孩子一天一条主计划，加餐用 seq_no 区分）
CREATE TABLE study_plans (
  id            BIGSERIAL PRIMARY KEY,
  child_id      BIGINT NOT NULL REFERENCES children(id),
  plan_date     DATE NOT NULL,
  seq_no        SMALLINT NOT NULL DEFAULT 1,   -- 1=主计划，2+=加餐
  status        VARCHAR(20) NOT NULL DEFAULT 'pending', -- pending|doing|done
  target_count  INT NOT NULL,
  done_count    INT NOT NULL DEFAULT 0,
  correct_count INT NOT NULL DEFAULT 0,
  stars         SMALLINT NOT NULL DEFAULT 0,
  duration_sec  INT NOT NULL DEFAULT 0,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  started_at    TIMESTAMPTZ,
  completed_at  TIMESTAMPTZ,
  UNIQUE (child_id, plan_date, seq_no)
);

-- 计划里的每一题（生成时固定，支持中断续做）
CREATE TABLE plan_items (
  id           BIGSERIAL PRIMARY KEY,
  plan_id      BIGINT NOT NULL REFERENCES study_plans(id) ON DELETE CASCADE,
  seq          SMALLINT NOT NULL,
  kp_id        BIGINT NOT NULL REFERENCES knowledge_points(id),
  question_id  BIGINT NOT NULL REFERENCES questions(id),
  bucket       VARCHAR(20) NOT NULL,  -- review|shaky|learning|new
  status       VARCHAR(20) NOT NULL DEFAULT 'pending', -- pending|correct|wrong|skipped
  tries        SMALLINT NOT NULL DEFAULT 0,
  cost_ms      INT NOT NULL DEFAULT 0,
  answered_at  TIMESTAMPTZ,
  UNIQUE (plan_id, seq)
);
CREATE INDEX idx_plan_items_plan ON plan_items(plan_id, seq);

ALTER TABLE subjects ADD COLUMN quiz_enabled BOOLEAN NOT NULL DEFAULT false;
```

### 与掌握度的关系

`plan_items` 只管「这道题在计划里做完了没」，**掌握度依然只由 `attempts` 决定**。答题时两件事一起发生（同一事务）：

```
POST /plans/:pid/items/:itemId/answer
  → 校验 item 属于该孩子且未完成
  → 判题（答案在服务端，不下发给前端）
  → 写 attempts（source=quiz，client_id = "plan-{itemId}-try{n}"，天然幂等）
    → 触发已有写链路：mastery_states 更新 + daily_stats 累加 + 新掌握发小红花
  → 更新 plan_items.status / tries / cost_ms
  → 更新 study_plans.done_count / correct_count
  → 返回：对错 + 正确选项 + 该知识点的新掌握状态
```

好处是家长看板不用改一行代码就能看到孩子今天的练习——因为数据源是同一张 `attempts`。

**答案不下发**：`GET /plans/today` 返回的题目里不含 `answer` 字段，判题在服务端。孩子翻不到答案，掌握度数据也才可信。

## 6. API

沿用 `/api/v1/children/:cid` 前缀与 `{data, error}` 包装。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/plans/today` | 取今日主计划；不存在则生成。返回计划 + 全部题目（无答案）+ 已答状态 |
| POST | `/plans/:pid/start` | 标记开始（写 `started_at`，用于统计真实时长） |
| POST | `/plans/:pid/items/:itemId/answer` | 提交一题：`{option_index, cost_ms}` → 返回对错 + 正确项 + 掌握状态 |
| POST | `/plans/:pid/finish` | 结算：算星星、写时长、返回获得的小红花 |
| POST | `/plans/extra` | 加餐：生成当天下一个 `seq_no` 的计划 |
| GET | `/plans?from=&to=` | 计划历史（家长端日历/趋势用） |

`GET /plans/today` 响应示例：

```json
{
  "data": {
    "plan": {
      "id": 12, "plan_date": "2026-08-22", "seq_no": 1,
      "status": "doing", "target_count": 10, "done_count": 3,
      "correct_count": 3, "stars": 0
    },
    "items": [
      {
        "id": 101, "seq": 1, "status": "correct", "bucket": "review",
        "kp": { "id": 63, "title": "2+5", "subject_name": "算术" },
        "question": {
          "id": 900, "type": "choice",
          "stem": "2 + 5 = ?",
          "visual": { "kind": "add", "a": 2, "b": 5, "emoji": "🍎" },
          "speech": { "text": "二加五等于几", "lang": "zh-CN" },
          "options": [{ "label": "6" }, { "label": "7" }, { "label": "8" }, { "label": "5" }]
        }
      }
    ]
  }
}
```

`visual` 给前端画图用（苹果排列、图形 emoji），`speech` 给读题按钮用，`options` 只有展示内容、没有 `correct` 标记。

## 7. iPad 答题端设计

### 路由（与家长端同一个前端应用，不同壳）

```
/kid          今日计划封面：大头像 + 「开始今天的练习」大按钮 + 已完成时显示星星
/kid/quiz     答题页：一题一屏
/kid/done     结算页：星星动画 + 获得的小红花 + 「再来一组」
```

家长端 `/` 那套侧边栏在 `/kid` 下完全不出现——孩子端不该看到数据看板，也不该能点进去改东西。两者共用 API 客户端和状态色板，但布局组件独立。

### 一题一屏的布局（iPad 横屏 1024×768 基准）

```
┌──────────────────────────────────────────┐
│ ●●●○○○○○○○            🌸 12      [退出]  │  进度点（已答=实心）
├──────────────────────────────────────────┤
│                                          │
│      🍎🍎  +  🍎🍎🍎🍎🍎                    │  视觉区（emoji 具象化）
│                                          │
│           2 + 5 = ?        [🔊 读题]      │  题干 56px
│                                          │
│    ┌────────┐  ┌────────┐                │
│    │   6    │  │   7    │                │  2×2 选项
│    ├────────┤  ├────────┤                │  每格 ≥ 200×120px
│    │   8    │  │   5    │                │
│    └────────┘  └────────┘                │
└──────────────────────────────────────────┘
```

关键交互细节：
- **无滚动**：整题必须一屏放完，用 `100dvh` + flex 居中，避免 iPad Safari 地址栏导致的高度跳动。
- **点击区 ≥ 88×88pt**，选项之间留 24px 间距，防误触。
- **提交后锁定 800ms**：孩子会连点，不锁会直接跳过下一题。
- **答对**：绿色勾 + 上扬音效 + 900ms 后自动进下一题。
- **答错**：红色描边 + 轻微抖动 + 语音「再想想」，同题重来一次；第二次仍错则高亮正确项、停留 2 秒后跳过。
- **退出**：右上角小按钮 + 二次确认，防止孩子误退；进度已存服务端，回来能续做。

### 读题：Web Speech API

```ts
const speak = (text: string, lang: 'zh-CN' | 'en-US') => {
  const u = new SpeechSynthesisUtterance(text);
  u.lang = lang;
  u.rate = 0.85;          // 放慢，5 岁孩子听得清
  speechSynthesis.cancel(); // 打断上一句，避免叠音
  speechSynthesis.speak(u);
};
```

iPad Safari 自带中英文语音，不需要后端 TTS、不产生流量费用。每道题进入时自动读一次，20 秒未作答再读一次，也可以手动点 🔊 重听。

英语题固定用 `en-US` 读单词、`zh-CN` 读指令，两段之间要留停顿（拆成两次 `speak` 串联），否则中英混读会串味。

### 加到主屏（PWA）

对应原型截图里的「添加到桌面」：加 `manifest.json` + `apple-mobile-web-app-capable`，从主屏图标进入时是全屏无地址栏，孩子不会误触浏览器 UI。v1 只做「可安装 + 全屏」，不做 Service Worker 离线缓存。

## 9. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| Q1 | `subjects.quiz_enabled` 迁移 + 出题生成器（算术/拼音/识字/英语）+ `-mode=questions` | 库里有 443+ 个知识点、900+ 道题，干扰项肉眼检查合理 |

## 10. 风险与取舍

1. **自动出题的质量天花板**：干扰项算法能保证「不容易蒙对」，但保证不了「教学上最优」。做法是先跑起来收集数据——如果某个知识点连续多次全对且耗时极短，说明题出得太简单，后续按真实作答数据调整生成规则。
2. **识字题依赖 TTS 读音准确度**：「一」「衣」这类同音字，光靠读音无法区分。识字题的干扰项要**排除同音字**，只用形近字，否则孩子答错不是因为不认字。
3. **孩子乱点也能攒对**：四选一有 25% 蒙对率。掌握度引擎要求连对 3~5 次才算掌握，单次蒙对不足以晋级，但会稍微拉高掌握速度。可接受，必要时给「耗时 < 1.5 秒的正确作答」打折计入。
4. **计划做不完**：状态停在 `doing`，第二天生成新计划时旧的自动作废（不补做）。5 岁孩子的计划不该有「欠账」压力。

## 11. 已确认的决策（2026-08-22）

1. **题量 10 题**，约 6~8 分钟，一天一个主计划 + 家长可手动加餐。
2. **识字题用「听读音选字」**：TTS 读字音，四个形近字里点选。干扰项**必须排除同音字**，否则孩子答错不是因为不认字——这要求给 130 个汉字配一份拼音表用于同音判定。
3. **只做答对/答错短音效，不加背景音乐**，避免干扰专注。
4. 直接开工，从 Q1 出题生成器开始。

## 12. 落地记录与方案偏差（Q1~Q5 已完成）

方案是写在动手之前的，下面这些是实现过程中改掉的地方，以实现为准。

### 题库实际产出

| 学科 | 可出题知识点 | 生成题数 |
|---|---|---|
| 算术 | 68 | 136 |
| 拼音 | 45 | 89 |
| 识字 | 130 | 260 |
| 英语 | 200 | 367 |
| 科普 | 99 | 198 |
| 古诗 | 50 | 100 |
| 逻辑 | 62 | 124 |
| **合计** | **654** | **1274** |

`questions` 表加了三列支撑这套自动出题：`code`（变体标识，和 `kp_id` 组成唯一索引，保证重复执行 seed 幂等）、`visual`（前端画图用）、`speech`（读题用）。

**英语的时间词砍掉了图片变体**。`morning`/`noon`/`afternoon`/`evening`/`night` 原本想用 🌅🌞🌇🌆🌃 出「看图选词」，但这五个 emoji 在 iPad 上肉眼几乎分不出来，孩子只能靠蒙。这类词现在只保留「听音选词」一个变体——**分不清的图不如不给图**。

**科普 / 古诗 / 逻辑已补真实内容并可出题**（2026-08-22）。游戏科仍是占位，不开 `quiz_enabled`。

### 与方案不同的决策

| 项 | 方案 | 实现 | 原因 |
|---|---|---|---|
| 每天计划数上限 | 1 主 + 1 加餐 | 1 主 + **2** 加餐（`maxPlansPerDay = 3`） | 留一点余量，但仍然有硬上限，防止变成刷题 |
| `GET /plans/today` | 返回主计划 | 返回当天**序号最大**的计划 | 否则加餐后刷新页面会被扔回已经做完的主计划 |
| 计划用时 | `completed_at - started_at` | `SUM(plan_items.cost_ms)` | 孩子做两题跑去玩、晚上回来接着做是常态，墙上时间会算出「练了 12 小时」 |
| 单题次数 | 未明确 | 最多 **2** 次（`maxTriesPerItem`） | 第一次错当场重来，第二次错给答案跳过，不追第三次 |
| 小红花 | 未明确 | `1 + stars` 朵（即 2~4 朵） | 一星也有奖励，不让「今天做得不够好」变成「今天什么都没得到」 |

### 学科轮转的一个坑

按学科分组轮询取题时，round-robin 的游标必须**跨桶保持**。最初每个桶各自从头开始轮，结果排序靠前的学科在四个桶里都被优先取到，一份计划里英语能占到 6 题，「最多 3 学科、单学科不超 5 题」的约束形同虚设。改成游标在整个组卷过程中持续推进后，学科分布才真的均匀。

### PWA 图标

`apple-touch-icon` **必须是 PNG**，iOS 不认 SVG——给 SVG 的话主屏图标会退化成网页截图。所以除了 manifest 里的 SVG，额外出了一张 `kid-icon-180.png`。
